# Tifa native Melee combat and ledge source archive

This package supplies 21 states and 84 native poses in three transparent 1024×2048 atlases. Every active state uses four drawn poses. `tifa-ledge` uses five active rows and three fully transparent inactive rows; the latter are not included in the pose count. The separate motion atlas package supplies the other 24 states of the 45-state set.

The base Tifa sprite and previous presentation atlas were inspected with `view_image` before prompting. The effective abilities were resolved with `resolveCombatAbility` before generation: simple `Direct de Tifa`, secondary `Beat Rush`, and 100% super `Final Heaven`. Therefore combat `special` and `chargeRelease` use physical Beat Rush punches. The separate prioritized Final Heaven animation is not replaced. Tifa keeps the original FFVII 1997 white top, black suspenders and skirt, red gloves and boots, long brown hair, and unarmed martial-arts identity.

`native-prompts.json` preserves the three initial requests. The first combat-a image contains seven native rows rather than the requested eight: its chargeLoop row is missing. The seven valid rows are retained, with chargeRelease and chargeRecovery explicitly mapped from source rows 5 and 6. One native corrective image supplies four held chargeLoop poses: rear-weighted chamber, deep squat, crossed bent forearms, and staggered high guard. None extends into a punch. No copied, stretched, procedural or empty row is counted as the missing animation.

The atlas registry records the actual source image, SHA256 and source row for every selected state. `provenance-combat.json` contains the source and reference archives, generation counts, selected mappings, prompts, normalization records and visual reviews. Model and generation identifiers are null because the native tool did not supply them. Local `exec-…png` output filenames are not represented as provider job identifiers.

`build-tifa-combat.mjs` uses the entity builder's exported `segmentAtlas` and `normalizeRow` helpers, nearest-neighbor normalization and transparent atlas assembly. Sharp only extracts, scales, pads and assembles the native artwork; it never invents limbs, poses, costumes or action frames. Each active cell is checked for visible pixels, a distinct native frame hash, and a transparent safe margin of ten pixels. All inactive cells are fully transparent. All selected column seams cross zero opaque or visible pixels.

The three normalized atlases and all 20 individual ledge crops were visually inspected. Every state has a concrete four-pose review record in the registry. These are newly generated 2D adaptations, not official FFVII assets or verified reproductions of original animation frames. Network verification and canonical 1:1 animation verification remain false.

Ledge hands use measured per-frame palm anchors instead of the feet baseline244. `normalization.contactAnchorMeasurements` records pixel coordinates, normalized coordinates and the real contact flag, with other visible hands listed separately. In ledgeHang, the leading palm centers are (156,24), (162,25), (171,25), and (171,24) in each 256px cell. Climb palms move from (192,76) and (210,103) to lower supporting points (212,205) and (229,205) as the body pulls above the inferred edge. Catch frame0 reaches toward the edge and has contact=false. Released drop/jump frames carry the preceding edge reference with contact=false; their free hands are listed without pretending they still grip the edge. No floor or ledge is painted into the sprites.
